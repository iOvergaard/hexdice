# Action-log check and `__hexdice` on the live site (23-11-2026)

## Why

Jacob copied a won 7-player game from the live site (seed 2953814395, Copy game on the end card). The record didn't replay: action 362 is Atlas attacking 3→16 while territory 3 is still Jacob's.

- Inserting one Atlas attack, 22→3, at index 361 (between 27→25 and 25→5) makes all 378 actions legal, and Jacob wins in round 16.
- With that action in place, the Normal AI's own choice matches every AI action in the log. So the live game played 22→3, but the action log never got it.
- Dropping or swapping any single action doesn't fix the log, so it's not a duplicated or reordered action.
- During Atlas's turn Jacob did nothing special (no Quit, reload or skip), on the live site at normal speed.

Not reproduced:
- the whole game on the dev build at instant speed, Jacob's 89 moves through `__hexdice` (all 378 actions logged, 22→3 at 361);
- Atlas's turn on the dev build at normal speed, loaded just before Jacob's round-14 end turn (logged `e,19-22,27-25,22-3,25-5,3-16,e`).

The live build differed from local main only in sea drawing and the landscape layout. Normal never draws from the AI's rng, so the `ai` field in the record says nothing about the missing action.

## What changed

- The controller keeps the state its action log leads to. Before it logs an action it checks that the board the action is played on is that state (`boardDiff` in `src/game/log-check.ts`). When it installs the result, it checks that no other action was logged while this one animated. Either problem goes to the console with a stack, to `__hexdice.problems()`, and into the Copy game record as `problems`.
- `window.__hexdice` is installed in every build, so a game on hexdice.snebold.dk can be driven and checked from the console.
